### Как происходит деплой

1. Ветка → Pull Request → CI и ревью напарника.
2. После merge в main Actions запускает `test` с PostgreSQL и `build` с lint и сборкой React.
3. `test`: `db:init` в локальной `agromarket_test`, два запуска `db:migrate`, сравнение данных, API-тесты.
4. Только после обеих зелёных проверок запускается `deploy`: Render deploy hook получает `ref=<github.sha>`.
5. Render: `npm ci --omit=dev`, затем `npm run db:migrate && npm start`. Auto-Deploy выключен, health path `/api/health`.
6. Smoke ждёт нужный SHA и доступную базу, проверяет каталог, 401 без токена, CORS, 404 и категории. Данные не изменяет.
7. Vercel собирает React из main автоматически; SPA rewrites возвращают `index.html` для прямых ссылок.
8. Авария: Rollback в Render, затем `git revert` через PR; актуальную версию можно вернуть повторным запуском push-main workflow.

Новый публичный маршрут: `GET /api/categories` → `[{ "name": "Овощи", "count": 4 }, ...]`. `count` — число. Категория `null`, если есть товар без категории, тоже учитывается в общей сумме.

## Лабораторная 9 — ответы

- **Предохранитель seed:** при нелокальном адресе без `--force` выводит `Отказ: db:init запущен НЕ на локальной базе — все данные будут удалены.` и подсказку `Если база пустая и вы уверены: node db/seed.js --force`. Он защищает от случайного DROP облачных таблиц. Проверка на настоящей Neon ещё предстоит.
- **Миграция:** создаёт только отсутствующие users, products и orders с теми же колонками и ограничениями, что в schema.sql; существующие данные сохраняет. Если заданы данные админа, добавляет его с `ON CONFLICT DO NOTHING`. Повторное выполнение не меняет результат — это идемпотентность.
- **Каталог на Vercel и CORS:** при разрешённом только localhost браузер не получает разрешающий заголовок для Origin Vercel. Нужно добавить точный Origin сайта в CORS_ORIGIN Render и выполнить деплой. Эксперимент пока не выполнен.
- **Почему deploy skipped в PR:** условие разрешает job только при push в main. Код PR должен сначала пройти тесты и ревью. `needs` запрещает деплой после неудачной проверки, `ref=SHA` выбирает именно проверенный коммит. Hook — секрет, потому что запускает деплой без дополнительного входа.
- **Почему Preview может не показать каталог:** у Preview Vercel собственный домен, которого нет в списке CORS. Его можно временно добавить явно; все чужие Origin разрешать нельзя.
- **Время от Merge до зелёного smoke:** не измерено — нужен первый облачный деплой. Записать фактическое время: ___ мин.
- **Сломанный деплой JWT_SECRET=123:** проверка конфигурации завершает новый процесс с кодом 1 и сообщением о коротком ключе. По ожидаемому сценарию Render старая версия продолжает обслуживать запросы, пока новая не прошла health check. Фактическую доступность и SHA нужно зафиксировать в эксперименте: ___.
- **Rollback или revert:** ночью при аварии быстро вернуть проверенный выпуск через Rollback; затем оформить `git revert` через PR, чтобы main и продакшен совпали. Rollback меняет запущенный выпуск без нового коммита, revert создаёт отменяющий коммит и проходит CI. Реальный откат пока не выполнен.
- **Холодный старт:** первый ответ ___ с, повторный ___ с — измерить после 20 минут без запросов. Причина возможной задержки — пробуждение бесплатного сервера и базы. Пользователю: «Сервер просыпается, это может занять до минуты». Фактические ограничения нужно сверить в текущих тарифах своих сервисов.
- **Использование ИИ:** да, Codex помог адаптировать сервер к продакшену, подготовить миграции, CI/CD, smoke и тесты, исправить адрес API и дополнить документацию. Исходные неформальные тексты и названия товаров сохранены.

### Вопросы для защиты

1. **Части приложения и регион:** браузер получает React с Vercel, Express работает на Render, PostgreSQL — на Neon. Близость API и базы уменьшает задержку каждого SQL-запроса.
2. **Окружение:** Render читает переменные при запуске Node.js. Vite подставляет VITE_-значения при сборке, и они доступны каждому в JavaScript браузера; секретам там места нет.
3. **db:init и миграция:** init удаляет таблицы и подходит для локальной тестовой базы или первого заполнения пустой облачной с --force; миграция сохраняет данные и безопасна при повторном запуске.
4. **CORS:** браузер проверяет разрешение API читать ответ для другого Origin. Совпасть должны схема, домен и порт. CORS не заменяет JWT и проверку роли.
5. **trust proxy:** за Render настоящий IP приходит от доверенного прокси. Без настройки rate limiter может считать всех одним клиентом. Значение 1 предполагает один доверенный прокси перед приложением.
6. **Конвейер:** PR → CI + ревью → merge → test и build → deploy с needs/if/ref → smoke ожидаемой версии. Hook позволяет запустить деплой, поэтому хранится в Secrets.
7. **Smoke:** короткая проверка уже работающего выпуска. В отличие от интеграционных тестов на отдельной БД ничего не создаёт и не удаляет в production.
8. **Ошибки:** 500 может содержать внутреннюю структуру и адреса; 400 нужен клиенту для исправления ввода, поэтому его сообщение сохраняется.
9. **SIGTERM и конфигурация:** сервер прекращает принимать новые соединения, ждёт текущие запросы и закрывает pool. Некорректное окружение прерывает запуск сразу, чтобы плохой выпуск не принимал трафик.
10. **Сон сервера:** первый запрос после простоя может ждать запуска процесса; следующий обычно быстрее. Время измеряется в Network.
11. **Rollback и revert:** rollback — оперативная смена выпуска, revert — отмена изменений в истории через новый коммит и полный CI.
12. **Смена JWT_SECRET:** токены со старой подписью перестанут проходить проверку на новом сервере, пользователям придётся войти заново.

## Безопасность — лабораторная 11

Актуальные настройки ЛР11 ниже заменяют прежний лимит из ЛР9.

- **Helmet:** `X-Content-Type-Options: nosniff`, HSTS и остальные заголовки Helmet;
  `X-Powered-By` отсутствует.
- **CORS:** точные Origin из `CORS_ORIGINS` либо прежнего `CORS_ORIGIN` (первый имеет
  приоритет), через запятую. В примере только `http://localhost:5173`. Для Vercel добавить
  фактический HTTPS Origin без завершающего `/`. Чужой сайт не получает ACAO;
  запросы curl/серверов без Origin работают. CORS не заменяет JWT и проверку ролей.
- **Авторизация:** общий лимит `/api/auth/login` + `/api/auth/register`: **10 запросов
  с IP за 15 минут**, включая успешные и невалидные, затем **429**. `RateLimit` сообщает
  лимит, остаток и время сброса; `Retry-After` на 429 — секунды до повторной попытки.
  `trust proxy = 1` соответствует одному доверенному прокси Render. Счётчик в памяти
  отдельного процесса; для нескольких экземпляров нужен общий store.
- **Тесты:** при `NODE_ENV=test` лимит отключён, но специальные тесты включают его
  явно и проверяют реальные 21 запрос и отдельные IP. На Render ставить `NODE_ENV=production`.
- **Zod:** регистрация, вход, POST/PUT/PATCH товаров и POST заявок. Успешная проверка
  заменяет req.body очищенными данными и убирает неизвестные поля. Ошибка — 400 с
  `{ error, details: [{ field, message }] }`. Все маршруты с `/:id` проверяют положительный
  десятичный int32 до SQL; 2147483647 допустим, несуществующий объект возвращает 404.
- **Ограничения:** JSON ≤100 КБ; пароль регистрации ≥8 символов и ≤72 **байт UTF-8**;
  имя пользователя 2–100, название товара 2–200, категория 1–50, unit 1–20 символов.
  Цена — целое число 1–10 000 000 (SQL INTEGER), строка из формы преобразуется в число,
  null/boolean/пустая строка отвергаются. Image — HTTP(S) URL до 2048 символов.
  Заявка: email, целое количество 10–1 000 000, корректная календарная дата, комментарий ≤2000.
- **PATCH:** необязательные поля, но минимум одно известное поле. Столбцы выбираются
  из фиксированного списка, значения идут SQL-параметрами. PUT требует полный набор
  обязательных полей. Право записи осталось только у admin: роли farmer в этом проекте нет.
- **Клиент:** apiFetch сохраняет details; формы регистрации и товара показывают список
  ошибок полей, форма входа — текст ответа 429. Невалидные данные проверяются сервером
  независимо от React. При ошибке ввода данные формы сохраняются.

### Лабораторная 11 — ответы

1. **npm audit.** Обновлены совместимые зависимости: body-parser, qs, ip-address на сервере;
   Vite, source-map-js и транзитивный Zod у клиента. Применялся audit fix без --force.
   Nodemon перенесён в devDependencies. Остались предупреждения moderate вокруг minimatch:
   nodemon на сервере, eslint/@eslint/js/@eslint/config-array на клиенте. Автоматическое
   полное исправление предлагает сменить версии инструментов вне заданного диапазона;
   это не сделано без отдельной проверки совместимости. Они не включены в production
   dependencies; клиент публикует только dist. Dev-зависимости тоже могут быть опасны
   при обработке недоверенных файлов, поэтому замечания задокументированы, а не скрыты.
2. **Секреты.** Проверить историю нельзя: ZIP-копия не содержит .git. В текущей копии
   нет рабочих .env, только примеры. Демопароль и тестовые ключи относятся к локальной
   среде. В настоящем Git-клоне проверить историю; найденный реальный секрет нужно
   заменить на сервисе, простое удаление файла не делает старое значение недействительным.
3. **Mass assignment.** Регистрация и раньше явно записывала только name/email/password_hash,
   а роль user задавала БД: получить admin через role было нельзя. Теперь Zod дополнительно
   отбрасывает role до обработчика. Тест проверяет роль и в ответе, и непосредственно в БД.
4. **trust proxy.** Express должен видеть IP клиента за доверенным прокси, иначе лимит
   может оказаться общим для всех. Значение 1 предполагает один прокси; его нельзя слепо
   переносить на другую сетевую схему с доступным напрямую бэкендом.
5. **React недостаточно.** Форму можно обойти через curl/Postman. Серверная проверка
   не зависит от браузера и срабатывает до bcrypt/SQL. details помогают исправить ввод.
6. **Откат Vercel.** Время не измерено: развёрнутый сайт не подключён. Rollback возвращает
   предыдущий выпуск; git revert отменяет ошибочный коммит в main, иначе следующий деплой
   вернёт ошибку. Процедура и команды — в ../RELEASE.md.
7. **ИИ.** Codex использован для адаптации схем к реальным полям, тестов, аудита зависимостей,
   исправления форм и документации. Локальные результаты проверены инструментами;
   ссылки на PR, релизы и замеры облака не выдумывались.

### Команды для демонстрации

Запустить сайт через `../start-demo.command`. Затем 21 попытка входа (у свежего демосервера
нет накопленного счётчика):

```bash
for i in $(seq 1 21); do
  curl -s -o /dev/null -w '%{http_code} ' -X POST http://localhost:3000/api/auth/login \
    -H 'Content-Type: application/json' -d '{"email":"missing@example.test","password":"wrong"}'
done
curl -i http://localhost:3000/api/products
curl -i -H 'Origin: https://evil.example' http://localhost:3000/api/products
curl -i http://localhost:3000/api/products/abc
```

Цикл израсходует лимит вашего локального IP на 15 минут, включая регистрацию.
Для следующей демонстрации можно перезапустить временный демосервер (его БД тоже сбросится).
Отрицательную цену, пустой PATCH, роль admin, 413, Unicode-пароли и успешный PATCH проверяет
`npm run test:local`. Тесты не используют реальную DATABASE_URL и уничтожают только свою
базу в памяти после окончания. Обычный `npm test` предназначен для отдельной PostgreSQL
agromarket_test; CI использует PostgreSQL 17.

### Вопросы для защиты

- **Helmet:** nosniff запрещает угадывать MIME вместо указанного Content-Type; HSTS сообщает
  браузеру использовать HTTPS для домена. Helmet не заменяет валидацию и авторизацию.
- **CORS:** ограничивает чтение ответа JavaScript чужого сайта в браузере. Curl не реализует
  эту браузерную политику; сервер обязан самостоятельно проверять JWT, роль и ввод.
- **Brute force:** перебор паролей. Лимит замедляет массовые попытки на дорогих auth-маршрутах,
  не мешая читать каталог. Распределённый перебор с множества IP требует дополнительных мер.
- **400/401/403/413/429:** неверные данные / нет действующей авторизации / нет прав /
  слишком большое тело / превышен лимит запросов. 500 — неожиданная серверная ошибка;
  неверный id клиента должен давать 400, а не раскрывать ошибку PostgreSQL.
- **Ограничения размера:** уменьшают расход памяти и CPU; bcrypt учитывает первые 72 байта,
  поэтому проверяем UTF-8 байты, а не только число символов.
- **Версии:** PATCH для исправлений, MINOR для совместимых функций, MAJOR для несовместимого API.
  v1.0.0 будет первым опубликованным стабильным контрактом этой работы.
