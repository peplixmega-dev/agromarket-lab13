# Выпуск v1.1.0

1. Ревью `feat/orders` и зелёные проверки API, React и Chromium. Исходники обеих частей находятся в одном репозитории.
2. Проверить целевой проект и ветку Neon. В каталоге server с настроенной DATABASE_URL выполнить `npm run db:migrate`. Для БД ЛР12 достаточно миграции 013, для новой базы команда также создаёт базовые таблицы. Скрипт инициализации демоданных очищает таблицы и предназначен для отдельной локальной базы.
3. Выпустить API на Render. Убедиться, что /api/health отвечает 200, каталог содержит stock. На новой учебной базе создать продавца через ADMIN_EMAIL и ADMIN_PASSWORD при миграции, добавить товары и остатки через интерфейс продавца. У старых товаров после миграции остаток 0.
4. Развернуть client в Vercel с `VITE_API_URL=https://<хост-api>/api`. В CORS_ORIGIN на Render указать точный origin фронтенда. Выполнить `BASE_URL=https://<хост-сайта> npm run e2e:smoke` из корня.
5. Тестовым покупателем оформить одну покупку и отменить её. Проверить возврат остатка. Создать GitHub Release v1.1.0 на проверенном коммите с описанием из CHANGELOG.
6. Для отката повторно развернуть прежние версии клиента и API. Миграция дополняет базу, поэтому откат кода не требует удаления заказов или столбцов. На время отката обрабатывать уже принятые покупки через актуальную версию сервиса или администратором БД.

# Подготовка релиза v1.0.0 и откат

Проект — монорепозиторий: React в `client`, Express в `server`.
Поэтому достаточно одного тега и одного GitHub Release для обеих частей.
Этот файл — план релиза; публикация не выполнена. В текущей папке нет `.git`.

## До публикации

1. Перенести изменения в Git-клон исходного проекта, создать ветку `security/hardening`.
2. Выполнить `npm run setup`, затем `npm run test:server`, `npm test`,
   `npm run coverage`, `npm --prefix client run lint` и `npm --prefix client run build`.
3. Проверить `npm --prefix server audit --omit=dev` и аналогичную команду для client.
4. Установить Chromium (`cd client` → `npx playwright install chromium`) и выполнить
   `npm run e2e` из корня. На развёрнутом сайте выполнить `npm run e2e:prod` (только smoke чтения, ЛР12) с
   `E2E_BASE_URL=https://ваш-сайт`.
5. Открыть PR, получить ревью напарника, дождаться CI и слить. В настройках репозитория
   сделать jobs `test` и `build` обязательными. YAML не включает это правило автоматически.
6. Дождаться успешного деплоя обеих частей, smoke и production E2E. На Render задать
   `CORS_ORIGINS` (или прежний `CORS_ORIGIN`) с точными Origin разрешённых сайтов.
7. В GitHub Settings включить Dependabot alerts/security updates. Файл dependabot.yml
   задаёт регулярные обновления, но не заменяет настройки аккаунта.

## Тег и GitHub Release

Только после предыдущих проверок, в Git-клоне с настроенным origin:

```bash
git switch main
git pull --ff-only
git status --short
git tag -a v1.0.0 -m "АгроМаркет 1.0: каталог, заявки, JWT, тесты, защита API"
git push origin v1.0.0
```

В GitHub → Releases → Draft a new release выбрать тег, Generate release notes,
добавить изменения из CHANGELOG.md, проверить текст и Publish. Если тег уже существует,
его не перезаписывать: проверить, к какому релизу он относится.

## Тренировка отката

Проводить на доступном учебном деплое. Зафиксировать URL и текущий commit SHA.
В отдельной ветке временно заменить видимый заголовок на «СЛОМАНО», провести PR с ревью,
merge и дождаться деплоя. В Vercel выбрать предыдущий успешный деплой и выполнить
Instant Rollback / Promote to Production. Замерить время до восстановления страницы,
проверить каталог и вход. Затем сделать `git revert <SHA_ошибочного_коммита>`
в новой ветке, провести PR и merge, дождаться CI и корректного повторного деплоя.

Rollback меняет развернутый выпуск; revert исправляет историю кода. Без revert
следующий деплой из main вернёт ошибку. Текущее время отката: не измерено, облако
не подключено. Намеренно сломанный код в подготовленную локальную версию не включён.

Версии: 1.0.1 — исправления, 1.1.0 — совместимые возможности, 2.0.0 — несовместимый контракт.
