```bash
npm install
npm run dev
```

Для загрузки каталога и заявок нужен запущенный сервер из `../server`. В базе PostgreSQL товары берутся из `server/data/db.json` при запуске `npm run db:init` (осторожно: скрипт пересоздаёт таблицы).

## Лабораторная 9 — Vercel

Уточнение к старой инструкции выше: актуальная команда заполнения базы — `npm run db:init` из папки `server`; скрипта `seed` в package.json нет.

Скопируйте `.env.example` в `.env`. Локально `VITE_API_URL=http://localhost:3000/api`, на Vercel — фактический HTTPS-адрес Render с `/api`. Секретов в VITE_-переменных быть не должно. После изменения переменной на Vercel нужен Redeploy.

Конфигурация Vercel: Root Directory `client`, preset Vite, build `npm run build`, output `dist`. `vercel.json` возвращает `index.html` при прямом переходе на путь SPA. Origin сайта должен быть в CORS_ORIGIN на Render.

Проверки перед PR:

```bash
npm ci
npm run lint
npm run build
```

Вход с ролью admin открывает добавление товара и список заявок с контактами покупателей. Тексты, названия товаров и доставка из восьмой лабы сохранены.

## Тестирование — лабораторная 10

Нужен Node.js 22.22.2+ в ветке 22 LTS или 24.15+ в ветке 24 LTS (ограничение jsdom). Команды выполняются из `client/`:

```bash
npm ci
npm test                 # компонентные тесты, без настоящего API
npm run test:watch       # перезапуск при изменениях
npm run coverage         # таблица и coverage/index.html
npm run lint
npm run build
```

Компонентные тесты: Vitest + jsdom + React Testing Library + user-event. Они ищут элементы по ролям и label, подменяют только `fetch` и проверяют настоящий `apiFetch`. После каждого теста удаляются DOM, моки и localStorage. Playwright из `e2e/` исключён из запуска Vitest. Покрытие включает исходники, в том числе непротестированную админскую форму; исключены точка монтирования `main.jsx` и тестовые файлы. Минимум покрытия строк в CI — 60%.

### E2E локально

В свежем клоне сначала установить зависимости обеих частей (`npm run setup` в корне), затем:

```bash
npx playwright install chromium
npm run e2e
npm run e2e:report
```

Playwright сам собирает клиент и запускает Express на `http://127.0.0.1:3100` с PGlite в памяти на порту 55440. Настоящая DATABASE_URL не используется. После тестов сервер останавливается и временные данные пропадают. Обычную демоверсию на порту 3000 можно оставить запущенной. Если 3100/55440 заняты, освободить их; чужой сервер тесты автоматически не подхватывают.

На этом Mac Chromium уже установлен в `client/.playwright-browsers/`; конфигурация автоматически использует эту папку, если она есть. В свежем клоне используется стандартная установка Playwright. Для запуска на этом компьютере двойным кликом есть `../start-tests.command`: покрытие, lint и E2E. Он умеет использовать встроенный Node.js приложения, даже если Node не добавлен в PATH.

Сценарии проверяют: ответ настоящего API и карточки каталога; прямой переход на `/login`; регистрацию уникального покупателя → выход → повторный вход → восстановление сессии после перезагрузки → выбор товара → создание заявки; отказ гостю на `/admin`. Регистрация сразу авторизует пользователя. Уникальный email создаётся внутри теста через UUID, включая повторные попытки. Тесты не используют администратора и не изменяют чужие товары, пользователей или заявки.

### E2E на продакшене и CI

```bash
# macOS / Linux — подставить настоящий адрес сайта
E2E_BASE_URL=https://your-site.vercel.app npm run e2e:prod
```

В PowerShell: `$env:E2E_BASE_URL="https://your-site.vercel.app"; npm run e2e:prod`.
Также поддерживается переменная `PRODUCTION_URL`. Без HTTPS-адреса `e2e:prod` завершится с ошибкой, не заменяя продакшен локальной средой. На развёрнутом сайте должны быть эти изменения и хотя бы один товар.

В корневом `.github/workflows/ci.yml` job `build` выполняет lint → `npm test` → coverage → build на каждом PR и push в main. Серверный job ЛР9 сохранён. E2E находится в отдельном `.github/workflows/e2e.yml`: вручную через Actions → **E2E (production) → Run workflow** и ежедневно в **09:00 Asia/Almaty** (04:00 UTC). В GitHub → Settings → Secrets and variables → Actions → Variables нужно задать `PRODUCTION_URL`. При падении сохраняются HTML-отчёт, скриншот и trace на 7 дней.

В Settings → Branches / Rulesets для main нужно включить обязательные проверки `build` и `test` и ревью. Наличие YAML само по себе не запрещает merge. Проверка блокировки: отдельная ветка с поломанным обработчиком кнопки → PR → красный `build` → убедиться, что merge недоступен → закрыть PR без слияния.

Публичного деплоя и `.git` в предоставленной папке нет. Поэтому production E2E, Actions, PR, ревью напарника и правило запрета merge здесь ещё не проверены; результаты локального запуска не являются результатами продакшена.

### Кратко для защиты

- **Пирамида:** в основании быстрые изолированные проверки функций и React-компонентов; выше интеграция Express + PostgreSQL (Supertest из ЛР8); наверху немного E2E для основных действий покупателя. E2E дороже и зависят от браузера, сети и данных.
- **jsdom:** реализация DOM в Node.js, без настоящей отрисовки браузера. Подходит для событий и структуры, но не доказывает правильность вёрстки, размеров, поведения CSS и настоящего браузерного окружения.
- **Роли и label:** отражают пользовательский интерфейс и его доступность; изменение CSS не должно ломать тест поведения. `data-testid` оставлен для границ повторяющихся карточек.
- **Запросы RTL:** `getBy` немедленно требует элемент; `queryBy` возвращает null при отсутствии; `findBy` ожидает асинхронное появление. При нескольких совпадениях нужно уточнить область через `within`.
- **Мок fetch:** управляемый ответ вместо настоящего сервера, чтобы воспроизводить загрузку, данные, пустой ответ, 500 и сетевой сбой. Если структура мока отличается от API, тест может проходить при сломанной интеграции, поэтому дополнительно нужен E2E.
- **Три состояния:** загрузка, успех с данными, ошибка. Пустой успешный ответ — отдельный случай; его нельзя путать с ошибкой.
- **Шпион `vi.fn()`:** сохраняет вызовы и аргументы. `toHaveBeenCalledWith` проверяет переданные данные, `not.toHaveBeenCalled` подтверждает, что невалидная форма ничего не отправила.
- **E2E, smoke, Supertest:** E2E проходит интерфейс в браузере; smoke быстро проверяет жизнеспособность развёрнутого API; Supertest вызывает Express напрямую без браузера, на отдельной тестовой БД.
- **JWT:** в тесте токен кладётся в localStorage до render; заголовок проверяется через `new Headers(options.headers).get('Authorization')`. Проверены 401 защищённых `/auth/me` и `/orders`. POST заявки в текущем сервере разрешён и гостям; его тест 401 проверяет обработку такого ответа интерфейсом, а реальное ограничение доступа проверяется на GET списка заявок.
- **Trace и секреты:** trace может содержать запросы и токены. В этих экспериментах использована только временная локальная база; production-артефакты стоит хранить в закрытом репозитории с ограниченным сроком хранения.

Документация: [Vitest — coverage](https://vitest.dev/guide/coverage), [Playwright — webServer](https://playwright.dev/docs/test-webserver), [Playwright — trace и screenshot](https://playwright.dev/docs/test-use-options).


## Лабораторная 11 — ошибки API

Форма регистрации и форма нового товара выводят details ответа 400 списком с названиями
полей. При 429 показывается сообщение сервера «Слишком много попыток…». apiFetch сохраняет
status и details; повторная отправка и смена режима очищают прежние ошибки. Форма товара
теперь имеет label, ограничения длины и положительной целой цены, обязательную категорию.

Проверки ЛР11: 30 тестов React, покрытие строк 95,2%; lint пройден. Раздел ЛР10 выше
содержит исторические результаты предыдущей работы. Порядок релиза и отката —
[RELEASE.md](../RELEASE.md), аудит сервера — [server/README.md](../server/README.md#безопасность--лабораторная-11).
Версия package.json подготовлена как 1.0.0; публичный тег и релиз пока не созданы.
